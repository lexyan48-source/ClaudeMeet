# ClaudeMeet — рекордер созвонов для Windows

Фоновый наблюдатель, который сам замечает начало созвона и записывает его: звук обеих
сторон и дешёвое видео экрана. После созвона запись сама расшифровывается локально
(faster-whisper), о старте, конце и готовой расшифровке приходят уведомления. За тем,
что наблюдатель жив, следит отдельный сторож (watchdog).

## Как это работает

Рекордер не знает про платформы. Он ловит сам факт того, что какое-то приложение взяло
микрофон — через реестр Windows, ветку
`CapabilityAccessManager\ConsentStore\microphone`. У каждого приложения там лежат
`LastUsedTimeStart` и `LastUsedTimeStop`; `Stop == 0` при ненулевом `Start` значит,
что микрофон занят прямо сейчас. Поэтому одинаково пишутся Zoom, Teams, Google Meet,
Яндекс Телемост, МТС Линк, Контур.Толк, Discord и звонок в Telegram.

Логика по умолчанию:

- микрофон занят дольше **30 секунд** → запись начинается;
- микрофон освободился → ждём **90 секунд** (вдруг переподключение) → запись закрывается;
- запись короче **2 минут** считается ложным срабатыванием и удаляется целиком;
- предохранитель: через **3 часа** запись закрывается в любом случае;
- закрытые записи по одной расшифровываются в фоне, только когда запись не идёт.

Что появляется в каждой папке `recordings\ГГГГ-ММ-ДД_ЧЧММ_Тема\`:

| Файл | Что внутри |
|---|---|
| `audio.wav` | обе дорожки сведены, 16000 Гц, моно, PCM 16 бит |
| `mic.wav`, `system.wav` | микрофон и системный звук по отдельности (если `keep_separate_tracks: true`) |
| `screen.mp4` | экран, 2 кадра в секунду, час — десятки мегабайт |
| `meta.json` | время, длительность, какое приложение держало микрофон, заголовки окон, устройства, уровни дорожек |
| `transcript_raw.txt` | расшифровка с таймкодами |
| `_recorder.log`, `whisper.log` | логи записи и расшифровки |

Пока идёт запись, в `recordings\` лежит файл `ЗАПИСЬ_ИДЁТ.txt`.

## Требования

- Windows 10 или 11.
- Python 3.10+ (проверялось на 3.13). Скрипты сначала ищут
  `%LOCALAPPDATA%\Programs\Python\Python313\python.exe`, потом `python` из `PATH`.
- Пакеты: `PyAudioWPatch` (форк PyAudio с WASAPI loopback — без него не записать
  собеседников), `numpy`, `faster-whisper` (для расшифровки).
- `ffmpeg` — только для видео экрана. Берётся из `PATH` или из подпапки `ffmpeg\bin\`
  рядом со скриптами. Без него звук пишется, видео нет.

## Установка

1. Скопируйте папку куда угодно, например `D:\ClaudeMeet`. Все скрипты находят
   свои файлы относительно себя.
2. Скопируйте `meet_config.example.json` в `meet_config.json` и при желании поправьте
   (см. ниже). Без файла работают значения по умолчанию.
3. `install.bat` — ставит `PyAudioWPatch`, проверяет numpy и ffmpeg, выводит список
   аудиоустройств. В конце должны быть `PyAudioWPatch OK` и `loopback ustroystv: N`, N > 0.
4. `python -m pip install numpy` — если numpy ещё не стоит (`install.bat` его только проверяет).
5. Для расшифровки: `python -m pip install faster-whisper`. Модель скачается при первом запуске.
6. `check.bat` — самодиагностика по 10 пунктам, итог в строке **ВЕРДИКТ**. Если пункт
   про реестр пишет «ветка пуста» — один раз включите микрофон в любой программе и
   запустите проверку ещё раз.
7. `test_audio.bat` — 10 секунд записи. Пока идёт отсчёт, говорите в микрофон и
   включите любой звук на компьютере. Нужно «слышно нормально» по обеим дорожкам.
   Без участия человека: `test_audio_auto.bat` (играет тон через ffmpeg).
8. `test_detect.bat` (по желанию) — 30 секунд печатает, кто держит микрофон. `+` перед
   именем — по этому приложению запись начнётся.

## Запуск

Автозапуск при входе в Windows — один из двух вариантов:

- `setup_task.bat` (запускать от имени администратора) — задача Планировщика `ClaudeMeet_Watcher` (вход в систему + 1 минута,
  работает от батареи, второй экземпляр не запускается). Задача стартует сразу.
- `setup_startup.bat` — без прав администратора: кладёт `ClaudeMeet.vbs` в папку
  автозагрузки пользователя.

Сторож: `install_watchdog.bat` заводит задачу `ClaudeMeet_Watchdog` (при входе и каждые
5 минут). Он поднимает наблюдателя, если тот не запущен, и перезапускает его, если
`logs\heartbeat.txt` не обновлялся дольше 5 минут. Заодно `diag_power.ps1` собирает
в `logs\power_events.txt` события питания и сбоев Windows за последние 3 дня.

Вручную:

| Файл | Что делает |
|---|---|
| `run_meet_recorder.bat` | запустить наблюдателя в текущем окне (вывод в `logs\_runner.log`) |
| `watcher_hidden.vbs` | то же без окна |
| `restart_watcher.bat` | перезапустить наблюдателя и проверить уведомление |
| `record_now.bat` | начать запись сейчас, не дожидаясь детекта (наблюдатель должен быть запущен) |
| `stop_now.bat` | закрыть текущую запись |
| `transcribe.bat [папка] [модель]` | расшифровать запись вручную (по умолчанию последнюю, модель `small`) |
| `notify_test.bat` | проверить все каналы уведомлений |
| `list_devices.bat` | список аудиоустройств |

Режимы самого скрипта: `python meet_recorder.py` (наблюдатель), `--test-audio`,
`--test-detect`, `--record-now`, `--stop`, `--list-devices`,
`--cleanup [--dry-run]`.

## Остановка и удаление

```
schtasks /end /tn ClaudeMeet_Watcher
schtasks /delete /tn ClaudeMeet_Watcher /f
schtasks /delete /tn ClaudeMeet_Watchdog /f
```

Если использовался `setup_startup.bat` — удалите
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\ClaudeMeet.vbs`.
Затем завершите процесс (`restart_watcher.bat` показывает, как его найти) и удалите папку,
предварительно забрав нужные записи. В реестр рекордер не пишет — только читает ветку
разрешений микрофона.

## Настройки

`meet_config.json` рядом со скриптом. Все параметры с пояснениями —
в [`meet_config.README.md`](meet_config.README.md). Главные:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `base_dir`, `recordings_dir`, `logs_dir` | папка скрипта, `recordings`, `logs` | пусто = по умолчанию |
| `ffmpeg_path`, `ffprobe_path` | из `PATH` или `ffmpeg\bin\` | пусто = по умолчанию |
| `min_hold_seconds` | `30` | сколько микрофон должен быть занят до старта записи |
| `stop_grace_seconds` | `90` | сколько ждать после освобождения микрофона |
| `min_meeting_seconds` | `120` | более короткие записи удаляются |
| `max_meeting_minutes` | `180` | предохранитель длины одной записи |
| `watch_processes` / `ignore_processes` | список | белый и чёрный списки приложений (подстрока имени exe; `"*"` — любое) |
| `loopback_device_name`, `mic_device_name` | `""` | кусок имени устройства, если автовыбор ошибся |
| `record_audio`, `record_screen` | `true` | что писать |
| `auto_transcribe`, `transcribe_model` | `true`, `small` | фоновая расшифровка |
| `retention_enabled`, `retention_audio_days`, `retention_screen_days` | `true`, `14`, `30` | удалять старые `audio.wav` / `screen.mp4`, но только у расшифрованных записей |
| `notify_toast`, `notify_balloon` | `true` | уведомления Windows |
| `notify_telegram` | `true` (в примере `false`) | уведомления в Telegram |
| `telegram_bot_token`, `telegram_chat_id` | `""` | ваш бот и чат; пока пусто — Telegram молча пропускается |
| `tg_config_path` | `""` | необязательно: отдельный JSON с `report_bot_token` и `report_chat_id` |

`meet_config.json` не попадает в git (см. `.gitignore`): в нём может лежать токен бота.

## Если что-то не так

**Молчит `system.wav` (не слышно собеседников).** Windows часто отдаёт звук конференций
в устройство роли «Связь», а не в устройство по умолчанию. Рекордер пробует устройство
по умолчанию, меряет уровень первых 3 секунд, при тишине перебирает остальные loopback и
перепроверяет на 60-й и 150-й секунде. Если не помогло — `list_devices.bat`, найдите
устройство с `LOOP = да`, через которое вы слышите собеседников, и впишите кусок имени в
`loopback_device_name`. Строка «LOOPBACK НЕ НАЙДЕН ВООБЩЕ» в логе значит, что стоит
обычный PyAudio: `python -m pip uninstall pyaudio`, затем `install.bat`.

**Молчит `mic.wav`.** Параметры → Конфиденциальность → Микрофон: доступ для классических
приложений включён; проверьте устройство ввода по умолчанию или задайте `mic_device_name`.

**Записи не появляются.** «РАБОТАЮ НА РЕЗЕРВЕ» в логе — ветка реестра пуста, один раз
воспользуйтесь микрофоном. «НЕ НАЧИНАЮ ЗАПИСЬ: свободно X ГБ» — мало места (порог
`min_free_gb`). Приложение не в белом списке — проверьте `test_detect.bat` и добавьте
имя в `watch_processes`. «Считаю это ложным срабатыванием» — созвон короче
`min_meeting_seconds`.

**Нет `screen.mp4`.** Ищите в логе «Видео экрана НЕ пишется» — обычно не найден ffmpeg.

**Нет уведомлений.** `notify_test.bat` покажет, какие каналы работают, причины — в логе.

**Наблюдатель падает или зависает.** Поставьте сторожа (`install_watchdog.bat`) и
смотрите `logs\watchdog.log`.

| Лог | Про что |
|---|---|
| `logs\meet_recorder.log` | общий лог наблюдателя (ротация при 5 МБ) |
| `logs\_runner.log` | вывод обёртки `run_meet_recorder.bat` |
| `logs\watchdog.log` | сторож |
| `recordings\<папка>\_recorder.log` | конкретный созвон |
| `check_log.txt`, `install_log.txt` | последняя диагностика и установка |

## Важно

Записывать разговор без ведома собеседников во многих странах незаконно. Предупреждайте
участников о записи.

## Где держать папку

Путь к папке — только латиница, без пробелов с кириллицей: файлы `.vbs` автозапуска читаются Windows Script Host в кодировке системы, и путь с кириллицей автозапуск ломает.
