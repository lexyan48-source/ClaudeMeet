# meet_config.json — что означает каждый параметр

Файл лежит рядом с `meet_recorder.py`. Начните с копии `meet_config.example.json`. Если файла нет — берутся значения по умолчанию
(они же прописаны в начале `meet_recorder.py`, словарь `DEFAULT_CONFIG`).
Если файл сломан (лишняя запятая, кавычки-ёлочки) — скрипт **не запустится** и скажет об этом
прямым текстом. JSON не понимает комментариев, поэтому все пояснения — здесь.

Обратные слэши в путях удваивать: `"D:\\Records\\ClaudeMeet"`.

---

## Пути

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `base_dir` | папка со скриптом | Корень. Пусто — папка, где лежит `meet_recorder.py`. Внутри создаётся `state\` для файлов-флагов ручного старта/стопа. |
| `recordings_dir` | `<папка скрипта>\recordings` | Куда складываются папки записей `ГГГГ-ММ-ДД_ЧЧММ[_Тема]`. |
| `logs_dir` | `<папка скрипта>\logs` | Общий лог `meet_recorder.log` и файлы проверки звука `test_mic.wav`, `test_system.wav`. |
| `ffmpeg_path` | из `PATH`, иначе `<папка скрипта>\ffmpeg\bin\ffmpeg.exe` | Полный путь к ffmpeg. Пусто — значение по умолчанию. Нужен только для видео экрана. Если файла нет — звук всё равно пишется, а в лог падает строка «Видео экрана НЕ пишется». |
| `ffprobe_path` | из `PATH`, иначе `<папка скрипта>\ffmpeg\bin\ffprobe.exe` | Пока используется только диагностикой `check.bat`. |

## Детект созвона

Рекордер не знает про платформы. Он смотрит в реестр Windows, ветку
`HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone`
(и такую же в `HKLM`, и подветку `NonPackaged`). У каждого приложения там лежат
`LastUsedTimeStart` и `LastUsedTimeStop`. Если `Stop == 0`, а `Start` не ноль — приложение
держит микрофон **прямо сейчас**. Поэтому одинаково ловятся Телемост, Zoom, Meet, МТС Линк
и звонок в Telegram.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `poll_seconds` | `10` | Как часто опрашивается реестр. Меньше 2 не ставится. Влияет и на то, как быстро подхватывается ручной флаг. |
| `min_hold_seconds` | `30` | Сколько микрофон должен быть занят подряд, прежде чем начнётся запись. Ровно этим отсекаются голосовые в Telegram (они короче). Побочный эффект: первые 30 секунд созвона в запись **не попадут**. Уменьшать до 10–15 можно, но тогда каждое голосовое будет стартовать запись (её потом выбросит `min_meeting_seconds`, но диск подёргается). |
| `stop_grace_seconds` | `90` | Сколько ждать после освобождения микрофона, прежде чем закрыть запись. Нужно, чтобы созвон не рвался на переподключении или когда вы вышли и сразу зашли обратно. Эти 90 секунд тишины остаются в конце файла — это нормально. |
| `max_meeting_minutes` | `180` | Предохранитель. Если микрофон завис занятым (бывает при крэше Zoom), запись всё равно закроется через 3 часа. Если созвон реально продолжается — начнётся новая папка. |
| `min_meeting_seconds` | `120` | Записи короче 2 минут считаются ложным срабатыванием и **удаляются целиком вместе с папкой**. В лог при этом пишется строка «Считаю это ложным срабатыванием и удаляю папку». |
| `watch_processes` | список | Белый список. Сравнение — подстрока без учёта регистра, по имени exe. `"chrome"` поймает `chrome.exe` (Google Meet, МТС Линк, любой веб-созвон). Специальное значение `"*"` — писать при любом приложении, которое взяло микрофон. |
| `ignore_processes` | `obs64`, `Camera`, … | Чёрный список, проверяется **раньше** белого. Сюда стоит добавлять всё, что легально держит микрофон постоянно. |
| `use_tasklist_fallback` | `true` | Резерв на случай, если ветка реестра пуста (свежая система). Тогда детект идёт просто по наличию процессов из белого списка через `tasklist`. Это заметно хуже — Chrome запущен почти всегда — поэтому при переходе на резерв в лог падает явная строка «РАБОТАЮ НА РЕЗЕРВЕ». |

## Звук

Пишутся две дорожки: `system.wav` (через WASAPI loopback — то, что говорят собеседники)
и `mic.wav` (то, что говорите вы). Обе сразу приводятся к **16000 Гц, моно, PCM 16 бит** —
ровно тот формат, который ест faster-whisper. В конце они сводятся
в `audio.wav`.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `record_audio` | `true` | `false` — звук не пишется вообще (останется только видео). |
| `target_sample_rate` | `16000` | Частота на выходе. Менять незачем: Whisper всё равно ресемплит в 16000. |
| `loopback_device_name` | `""` (пусто) | **Главная ручка, если в записи тишина.** Кусок имени loopback-устройства. Пусто — берётся устройство вывода по умолчанию. Проблема в том, что Windows роутит звук конференций в роль **eCommunications** («Связь»), а не в multimedia-устройство: возьмёшь дефолт — запишешь тишину. Поэтому скрипт сначала пробует дефолт, меряет RMS первых `probe_seconds` секунд и, если тихо, перебирает остальные loopback. Если вы уже знаете нужное устройство (`--list-devices`) — впишите сюда кусок имени, например `"Realtek"` или `"Наушники"`. |
| `mic_device_name` | `""` | То же для микрофона. Пусто — устройство ввода по умолчанию. |
| `silence_rms_threshold` | `12` | Ниже этого RMS дорожка считается тишиной. По нему принимается решение переключить loopback и по нему же в `meta.json` ставится `"silent": true`. Поднимать, если в комнате сильный фон и «тишина» не детектится. |
| `probe_seconds` | `3` | Сколько секунд слушать каждое устройство при выборе. |
| `loopback_recheck_seconds` | `[60, 150]` | На каких секундах записи ещё раз проверить, не молчит ли системная дорожка. Если молчит — рекордер **на ходу** переезжает на следующее loopback-устройство и пишет об этом в лог. Спасает, когда в момент старта просто никто не говорил. Пустой список `[]` — не перепроверять. |
| `keep_separate_tracks` | `false` (с 11.10.2026) | Оставлять ли `mic.wav` и `system.wav` после сведения. `true` — оставлять (полезно: по отдельным дорожкам ясно, кто говорил). `false` — удалять после успешного сведения. |
| `retention_enabled` | `true` | Автоочистка старых записей. Рекордер раз в 6 часов (и через 10 минут после старта, когда запись не идёт) удаляет `audio.wav` и `screen.mp4` старых записей, **но только если у записи есть расшифровка** (`transcribe_info.json` + непустой `transcript_raw.txt` или `transcript.md`). `meta.json`, расшифровки и `frames` не трогаются. Ручной прогон: `python meet_recorder.py --cleanup --dry-run` (показать) или `--cleanup` (удалить). |
| `retention_audio_days` | `14` | Через сколько дней удалять `audio.wav`. `0` — не удалять. |
| `retention_screen_days` | `30` | Через сколько дней удалять `screen.mp4`. `0` — не удалять. Если вам нужны кадры из видео, достаньте их до этого срока. |
| `mix_mic_gain` | `1.0` | Усиление микрофона при сведении. `1.5` — если ваш голос тише собеседников. |
| `mix_system_gain` | `1.0` | То же для системного звука. |
| `audio_chunk_frames` | `2048` | Размер чанка чтения. Больше — меньше нагрузка, но грубее реакция на стоп. Трогать не нужно. |

Дорожки пишутся **инкрементально прямо во время записи**, и заголовок WAV
переписывается каждые 5 секунд. Поэтому если машина внезапно перезагрузится,
`mic.wav` и `system.wav` всё равно откроются плеером — потеряются только последние секунды.

## Экран

Пишется дешёвое видео, а не набор кадров: 2 кадра в секунду, h264 crf 32. Час укладывается
в десятки мегабайт. Смысл в том, что сначала разбирается текст, а кадры нарезаются постфактум
и только если из контекста ясно, что нужна картинка.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `record_screen` | `true` | `false` — видео не пишется. |
| `screen_framerate` | `2` | Кадров в секунду. Больше 5 ставить смысла нет, размер растёт линейно. |
| `screen_scale_width` | `1600` | Ширина после масштабирования, высота считается сама (`-2`, чтобы была чётной). |
| `screen_crf` | `32` | Качество h264: меньше = лучше и тяжелее. 28 — заметно чётче текст на слайдах, файл примерно вдвое больше. |
| `screen_preset` | `veryfast` | Пресет x264. `ultrafast` — меньше нагрузка на процессор, больше файл. |
| `screen_offset_x`, `screen_offset_y`, `screen_width`, `screen_height` | `0` | Захват конкретного монитора. Пока `screen_width` и `screen_height` равны нулю, снимается **весь рабочий стол целиком** (все мониторы одной картинкой). Чтобы снимать только второй монитор — впишите его смещение и размер, например `offset_x: 1920, offset_y: 0, width: 1920, height: 1080`. |

Останавливается ffmpeg корректно — посылкой `q` в stdin. Если его просто убить, mp4
останется без индекса и не откроется; на этот случай в логе будет строка про terminate/kill.

## Прочее

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `title_poll_seconds` | `30` | Как часто через `tasklist /v` собирать заголовки окон. Они целиком попадают в `meta.json` — у Телемоста в заголовке окна часто есть название встречи. |
| `topic_from_window` | `true` | Добавлять ли тему в имя папки. Кириллица транслитерируется (в `.bat` она ломается): `Планёрка отдела — Яндекс Телемост` → `2026-08-05_1430_Planerka_otdela`. Название самой программы из заголовка выбрасывается. |
| `min_free_gb` | `2.0` | Меньше этого свободного места — запись **не начинается**, в лог уходит «НЕ НАЧИНАЮ ЗАПИСЬ: свободно X ГБ». |
| `max_log_mb` | `5` | Ротация лога по размеру: при превышении текущий лог переезжает в `meet_recorder.log.1`, новый начинается с нуля. Хранится всегда два файла. |

## Расшифровка и уведомления

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `auto_transcribe` | `true` | Наблюдатель сам расшифровывает закрытые записи фоновой очередью (faster-whisper): по одной, только когда запись не идёт, от старых к новым. |
| `transcribe_model` | `small` | `tiny`, `base`, `small`, `medium`, `large-v2`, `large-v3`. `medium` точнее на цифрах и именах, но качается ~1.5 ГБ и считает втрое дольше. |
| `transcribe_scan_seconds` | `120` | Как часто пересматривать очередь. |
| `transcribe_start_delay_seconds` | `90` | Пауза после старта наблюдателя перед первой расшифровкой. |
| `notify_toast` | `true` | Уведомление Windows (toast). |
| `notify_balloon` | `true` | Резервное уведомление через значок в трее. |
| `notify_telegram` | `true` в коде, `false` в примере | Сообщения в Telegram. Работает, только если задан бот (ниже); иначе канал молча пропускается. |
| `telegram_bot_token` | `""` | Токен вашего бота от @BotFather. |
| `telegram_chat_id` | `""` | Чат, куда слать (число). |
| `tg_config_path` | `""` | Необязательно: путь к отдельному JSON с ключами `report_bot_token` и `report_chat_id` — если хотите держать токен вне `meet_config.json`. Используется, только когда два ключа выше пусты. |

## Куда смотреть, если что-то не так

1. `logs\meet_recorder.log` — общий лог наблюдателя.
2. `recordings\<папка записи>\_recorder.log` — лог конкретного созвона: какие устройства выбраны, были ли переключения по тишине, как закрылся ffmpeg.
3. `recordings\<папка записи>\meta.json` — поля `audio.mic.rms`, `audio.system.rms` и `silent`. Если `"silent": true` у системной дорожки — собеседников в записи нет, крутите `loopback_device_name`.
